# JavaScriptコーディング規約

## 1. 厳密等価演算子の優先使用
- JS-001 適用条件：JavaScriptの等価・不等価比較。
- JS-002 要求：等価比較は原則 `===`、不等価比較は原則 `!==` を使用し、`==`、`!=` より優先する。意図的な型変換を伴う比較が必要な場合は、理由を明確にしたうえで使用できる。
- JS-003 判定：比較対象の型、型変換の有無、変更前後の動作を確認する。単純な演算子置換で意味が変わる場合は自動修正せず、影響と判断事項を報告する。boolean型の条件判定には共通規約C-801〜C-803を併せて適用する。

## 2. varによる変数宣言の禁止
- JS-004 適用条件：JavaScriptの新規・変更部分における変数宣言。要求：`var` による変数宣言を禁止し、`const` または `let` を使用する。判定：適用対象に `var` による変数宣言が存在しないことを確認する。既存コードを修正する場合は、スコープ、巻き上げ、再宣言、初期化順序等による動作の変化がないことを確認する。意味の同一性を確認できない場合は自動修正しない。

## 3. constの優先使用
- JS-005 適用条件：JavaScriptの新規・変更部分における `let` または `const` による変数宣言。要求：宣言後に変数への再代入を行わない場合は、原則 `const` を使用する。再代入が必要な場合は `let` を使用する。判定：変数の宣言、初期化、再代入の有無を確認する。再代入がなく、宣言時に初期化可能な変数を `let` で宣言した場合は違反とする。`const` への変更により動作が変化する場合は自動修正しない。オブジェクトや配列の内部状態の変更は、変数そのものへの再代入と区別する。

## 4. シングルクォートの優先使用
- JS-006 適用条件：JavaScriptの新規・変更部分における通常の文字列リテラル。要求：通常の文字列リテラルは原則シングルクォートで記述する。許容条件：文字列内にシングルクォートが含まれ、ダブルクォートを使用することでエスケープを削減できる場合は、ダブルクォートを使用できる。文字列補間、複数行文字列等、テンプレートリテラルを必要とする場合はバッククォートを使用できる。判定：文字列リテラルの引用符と許容条件への該当性を確認する。引用符の変更では文字列値が維持されることを確認する。JSONなど、JavaScriptとは異なる構文規則が適用される部分は対象外とする。

## 5. 変数宣言の個別化
- JS-007 適用条件：JavaScriptの新規・変更部分における変数宣言。要求：原則として1つの変数宣言文では1つの変数宣言子だけを記述する。カンマ区切りによる複数宣言子の記述は禁止する。許容条件：`for` 文の初期化部分では、複数の変数宣言子を記述できる。判定：通常の変数宣言文に複数の宣言子が含まれていないことを確認する。`for` 文の初期化部分は許容する。宣言文を分割する場合は、初期化順序、スコープ、参照関係及び実行結果が維持されることを確認する。分割代入による1つの宣言子から複数変数への束縛は、複数宣言子とは区別する。

## 6. 適用及び検証の共通事項
- 既存の共通システム開発標準及び標準管理規程に従い、新規・変更部分を適用対象とする。未変更部分への一律の遡及修正は要求しない。
- 規約違反の検出と自動修正の可否判定を区別する。
- 修正によって動作が変化する可能性がある場合は、自動修正を停止し、影響と判断事項を報告する。
- 修正後は、変更箇所と影響する既存機能について、再実行可能な回帰テストを実施する。
