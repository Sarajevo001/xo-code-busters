# JavaScriptコーディング規約

## 1. 厳密等価演算子の優先使用
- JS-001 適用条件：JavaScriptの等価・不等価比較。
- JS-002 要求：等価比較は原則 `===`、不等価比較は原則 `!==` を使用し、`==`、`!=` より優先する。意図的な型変換を伴う比較が必要な場合は、理由を明確にしたうえで使用できる。
- JS-003 判定：比較対象の型、型変換の有無、変更前後の動作を確認する。単純な演算子置換で意味が変わる場合は自動修正せず、影響と判断事項を報告する。boolean型の条件判定には共通規約C-801〜C-803を併せて適用する。

## 1の2. 条件判定における暗黙の真偽変換
- **JS-016 目的・理由**：JavaScriptのtruthy/falsyによる暗黙変換で、正常な0件・空文字と契約違反の欠損値等を混同しない。共通規約C-005〜C-008、C-801〜C-803を具体化する。
  - **適用条件**：`if`、`while`、`for`、条件演算子`?:`などの条件判定及び`&&`・`||`・`!`等による判定式。非boolean値が真偽変換される場合を含む。
  - **要求**：件数・数値は`=== 0`、`!== 0`等、意図した比較を記述する。文字列は空文字かどうか、参照値は`null`・`undefined`等の許容範囲を契約に従い明示する。boolean値はC-802に従い`=== true`又は`=== false`等で明示する。欠損・不正値を`|| []`、`|| 0`等の無根拠な既定値で正常化しない。意図的なフォールバックは契約と理由を示す。
  - **判定**：式の値の型、許容値、正常・異常時の振る舞いを確認する。`if (!targets.length)`、`if (count)`、`if (name)`、`if (obj)`等、非boolean値の暗黙変換に依存する条件は違反。型・契約が未確認なら判定不能。比較への変更で`TypeError`等が新たに発生し得る場合は、契約違反が顕在化した可能性を確認し、例外を握り潰さず、異常系テストを行う。例外発生を無条件に正当化せず、適切な境界で安全に失敗を扱う。契約を確認できない機械的な置換はしない。
  - **適切例**：`if (targets.length === 0) {` は、`targets`が配列である契約を確認したうえで使用する。`targets`の欠損を許容する仕様なら、その分岐を別途明示する。`if (value === null)` はnullのみを判定する。`if (value === undefined)` はundefinedのみを判定する。
  - **不適切例**：`if (!targets.length)`、`if (targets)`、`const targets = response.targets || [];`（欠損が異常である契約の場合）。`if (targets?.length === 0)` は欠損時に単にfalseとなるため、欠損を異常とする契約ではそれだけで異常検出を満たさない。

## 2. varによる変数宣言の禁止
- JS-004 適用条件：JavaScriptの新規・変更部分における変数宣言。要求：`var` による変数宣言を禁止し、`const` または `let` を使用する。判定：適用対象に `var` による変数宣言が存在しないことを確認する。既存コードを修正する場合は、スコープ、巻き上げ、再宣言、初期化順序等による動作の変化がないことを確認する。意味の同一性を確認できない場合は自動修正しない。

## 3. constの優先使用
- JS-005 適用条件：JavaScriptの新規・変更部分における `let` または `const` による変数宣言。要求：宣言後に変数への再代入を行わない場合は、原則 `const` を使用する。再代入が必要な場合は `let` を使用する。判定：変数の宣言、初期化、再代入の有無を確認する。再代入がなく、宣言時に初期化可能な変数を `let` で宣言した場合は違反とする。`const` への変更により動作が変化する場合は自動修正しない。オブジェクトや配列の内部状態の変更は、変数そのものへの再代入と区別する。

## 4. シングルクォートの優先使用
- JS-006 適用条件：JavaScriptの新規・変更部分における通常の文字列リテラル。要求：通常の文字列リテラルは原則シングルクォートで記述する。許容条件：文字列内にシングルクォートが含まれ、ダブルクォートを使用することでエスケープを削減できる場合は、ダブルクォートを使用できる。文字列補間、複数行文字列等、テンプレートリテラルを必要とする場合はバッククォートを使用できる。判定：文字列リテラルの引用符と許容条件への該当性を確認する。引用符の変更では文字列値が維持されることを確認する。JSONなど、JavaScriptとは異なる構文規則が適用される部分は対象外とする。

## 5. 変数宣言の個別化
- JS-007 適用条件：JavaScriptの新規・変更部分における変数宣言。要求：原則として1つの変数宣言文では1つの変数宣言子だけを記述する。カンマ区切りによる複数宣言子の記述は禁止する。許容条件：`for` 文の初期化部分では、複数の変数宣言子を記述できる。判定：通常の変数宣言文に複数の宣言子が含まれていないことを確認する。`for` 文の初期化部分は許容する。宣言文を分割する場合は、初期化順序、スコープ、参照関係及び実行結果が維持されることを確認する。分割代入による1つの宣言子から複数変数への束縛は、複数宣言子とは区別する。

## 6. 文末セミコロンの明示
- JS-008 適用条件：JavaScriptの新規・変更部分において、構文上セミコロンで終端することができる文。要求：変数宣言文、式文、`return` 文、`throw` 文、`break` 文、`continue` 文など、セミコロンで終端する文は末尾にセミコロンを明示する。自動セミコロン挿入（ASI）による省略を前提としない。対象外：`if`、`for`、`while`、`switch`、`try` などの制御構文のブロック終端、および関数宣言・クラス宣言の終端など、文末セミコロンを必要としない構文。`for` 文のヘッダー内の区切り記号は、本規約で追加を要求する文末セミコロンとは区別する。判定：適用対象の文について、構文上の文末セミコロンが明示されていることを確認する。省略されている場合は違反とする。対象の構文または変更範囲を特定できない場合は判定不能とする。修正時の注意：セミコロンの追加によって構文解析結果や実行動作が変化する可能性がある場合は、機械的な自動修正を行わず、影響を確認する。既存未変更部分への一律遡及修正は要求しない。

## 7. 三項演算子のネスト禁止
- JS-009 適用条件：JavaScriptの新規・変更部分における条件演算子 `?:` の使用。要求：条件演算子の条件式・真の場合の式・偽の場合の式に、別の条件演算子を入れ子にしてはならない。許容条件：入れ子になっていない単独の条件演算子は使用できる。判定：AST上で、条件演算子の内部に別の条件演算子が存在する場合は違反とする。修正時の注意：`if` / `else if` / `else` などに展開する場合は、条件の評価順序、短絡評価、副作用、戻り値を維持する。機械的な修正によって動作の同一性を保証できない場合は、自動修正しない。既存未変更部分への一律遡及修正は要求しない。

## 8. 1行1文の原則
- JS-010 適用条件：JavaScriptの新規・変更部分における文及び変数宣言。要求：原則として1行に1つの文のみを記述する。セミコロンで区切って同一行に複数の独立した文又は変数宣言を記述することを禁止する。1つの文が長くなる場合は、可読性を考慮して複数行に分割してよい。分割時は構文上のまとまりと処理の意味が読み取りやすい位置で改行する。判定：同一行に複数の独立した文がある場合は違反とし、単一の文が複数行に分かれていても違反としない。 `for` 文のヘッダー内の区切りセミコロン及び文字列リテラル内のセミコロンは対象外とする。既存未変更部分への一律遡及修正は要求しない。

## 12. 適用及び検証の共通事項
- 既存の共通システム開発標準及び標準管理規程に従い、新規・変更部分を適用対象とする。未変更部分への一律の遡及修正は要求しない。
- 規約違反の検出と自動修正の可否判定を区別する。
- 修正によって動作が変化する可能性がある場合は、自動修正を停止し、影響と判断事項を報告する。
- 修正後は、変更箇所と影響する既存機能について、再実行可能な回帰テストを実施する。

## 9. インデント・処理ブロックの書式
- **JS-011 目的・理由**：構造の視認性と書式の一貫性を保つ。共通規約C-1101を具体化する。
  - 適用条件：JavaScriptの新規・変更部分。
  - 要求：1階層のインデントを半角空白2文字とし、タブをインデントに用いない。同じ階層の行を揃える。
  - 判定：階層ごとの空白数を確認し、不整列・幅の不統一・タブ使用は違反。構文の階層を特定できない場合は判定不能。
  - 例：関数直下の文は空白2文字、さらに内側のブロック直下は空白4文字。
- **JS-012 目的・理由**：関数・制御構文の宣言と本体を明確に分離する。共通規約C-1102及びC-804を具体化する。
  - 適用条件：関数宣言・関数式・メソッド・コンストラクタ・制御構文・ブロック本体のアロー関数など、波括弧が処理ブロックを表す場合。
  - 要求：`{` の直後と `}` の直前に必ず改行する。1文・空ブロック・短いアロー関数でも例外なし。`if (ok) { run(); }`、`() => { return 1; }`、`() => {}` は禁止。非ブロックの式形式アロー関数、オブジェクトリテラル、分割代入、import/exportの名前リストは処理ブロックではなく対象外。
  - 判定：AST等でブロック構文を特定し、開始・終了の同一行記述を違反とする。構文を判定できなければ判定不能。
  - 例：`function f() {\n  return 1;\n}` は遵守。

## 10. 演算子・区切り文字の空白と空行
- **JS-013 目的・理由**：式の境界と構文上の役割を見やすくする。共通規約C-1103を具体化する。
  - 適用条件：JavaScriptの新規・変更部分の演算子・区切り文字。
  - 要求：代入（`=`、`+=`等）、比較（`===`、`<`等）、算術（`+`、`/`等）、論理（`&&`、`||`、`??`）、ビット演算、関係演算、条件演算子`?`と`:`など、二項演算子・条件演算子の前後は空白1文字とする。単項演算子（`!`、単項`-`、`typeof`等）は構文に従い、`!`や単項`-`の直後には空白を置かない。`++`、`--`、`?.`、`.`、添字`[]`、呼び出し括弧`()`、文末`;`の前後に一律の空白を要求しない。カンマの後は、改行しない場合に空白1文字、カンマの前は空白なし。オブジェクトのキーと値の区切り`:`は後に空白1文字、前は空白なし。構文上の役割が異なる`:`（ラベル等）を同一視しない。字句や意味を変える空白は挿入しない。
  - 判定：演算子・区切り文字を構文に基づき分類して照合する。指定空白の欠落・過剰は違反。構文不明は判定不能。
  - 例：`turnNumber = 0;`、`const selected = ready ? a : b;`、`fn(a, b);` は遵守。`turnNumber=0;`、`ready?a:b` は違反。
- **JS-014 目的・理由**：処理単位の境界だけに空行を使用し、不要な視覚的分断を防ぐ。共通規約C-1104を具体化する。
  - 適用条件：JavaScriptの新規・変更部分。
  - 要求：意味のない空行及び2行以上連続する空行を禁止する。異なる処理単位の区切りには必要に応じて空行1行を使用する。文字列・テンプレートリテラルの内容は対象外。
  - 判定：空行の連続と前後の処理単位を確認する。意味のない空行・連続空行は違反。区切りの意味を確認できなければ判定不能。
  - 例：同じ役割の変数宣言間に2行の空行を置かない。

## 11. 外部依存・独自関数化
- **JS-015 目的・理由**：JavaScriptでも共通規約C-1201・C-1202の外部依存と抽象化の妥当性を維持する。
  - 適用条件・要求・判定：新規ライブラリ導入はC-1201に従う。jQuery等は標準APIで足りる用途には新規導入しない。既存DOM APIの短縮ラッパーはC-1202に従い評価する。単なる`$`という名前からjQuery使用と断定せず、実際の定義・読み込みを確認する。
