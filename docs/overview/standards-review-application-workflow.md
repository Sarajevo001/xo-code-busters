# 開発規約の確認・適用ワークフロー

- 記録日: 2026-11-08
- 状態: 合意した運用方針の記録。正式な開発規約の制定・改訂手続きとは区別する。
- 対象: 全プロジェクト共通規約、言語別規約、プロジェクト固有規約
- 関連正本: `standards/management.md`、`standards/operations.md`

## 1. 目的と原則

各プロジェクトで、適用対象となる規約を確認し、変更候補の報告と実際の変更を明確に分離する。
規約の種類によらず同じ確認・適用ワークフローを用いる。異なるのは規約の適用範囲、採用版、正本の管理場所である。

規約本文の新規制定・改訂・廃止は本ワークフローではなく、既存の標準管理規程と標準管理運用仕様に従う。

## 2. 規約の種類と正本

- 全プロジェクト共通規約: 明示的に採用したプロジェクトが対象。共通正本はXO-Code Bustersの`standards/`。
- 言語別規約: 採用したプロジェクトの該当言語・対象成果物が対象。共通正本は`standards/languages/`。
- プロジェクト固有規約: 当該プロジェクトが対象。原則として当該プロジェクトのリポジトリに正本を置く。

個別プロジェクトの確認時は、該当する規約をまとめて照合し、変更候補を一つの報告に集約する。正本の最新版と、当該プロジェクトが承認済みの適用版を混同しない。

## 3. 確認と適用の手順

### 3.1 確認依頼

ユーザーの例: 「規約を確認してください」

AIは、参照可能な正本、規約ID・版・コミットSHA、プロジェクトの採用版、適用対象を特定し、設計資料やソースコード等と照合する。
この段階では、ソースコード、規約参照情報、設計資料等を**変更しない**。参照情報が不足・不一致の場合は、その旨を報告し、確認できない範囲を推測で埋めない。

### 3.2 変更候補の報告

AIは「変更候補が○件あります」と報告し、候補ごとに次を示す。

- 候補IDと対象ファイル・箇所
- 根拠となる規約ID・版・条項
- 現状と提案する変更内容
- 変更理由、想定影響、依存関係
- 実施可能性と、追加判断・確認・検証が必要な事項

該当なしの場合は0件と報告する。確認できなかった範囲は0件に含めず、判定不能として区別する。

### 3.3 ユーザーの適用指示

ユーザーの例: 「全て適用してください」「候補1と3を適用してください」

「全て」は**直前に提示して識別した変更候補の全件**を指す。新たな候補や未提示の変更を暗黙に追加しない。
ユーザーは候補の詳細を質問し、全部・一部・保留を選べる。確認依頼だけでは適用を許可したとみなさない。

### 3.4 修正と検証

指示対象のうち、既存規程と承認範囲に照らして実施可能な変更を作業ブランチ等の隔離環境で実施し、必要な検証を行う。
新たな設計判断、規約間の矛盾、影響不明、権限不足、検証不能、承認が必要な例外等は、独断で進めず、理由と選択肢を提示して確認する。
「全て適用してください」は既定ブランチへの反映承認を意味しない。`main`等の既定ブランチへの反映は、対象と変更内容について別途明示承認を得る。
既存の標準管理規程・運用仕様に定める自動修正の制約は、本手順によって緩和されない。

### 3.5 結果報告

候補IDごとに、少なくとも以下を区別して報告する。

- 適用済み: 実施内容、変更箇所、検証方法・結果
- 適用不能: 実施できなかった理由と影響
- 判断待ち: 未確定の判断事項と選択肢
- 未実施・保留: ユーザー指示等により対象外となった事項

実施と検証を混同せず、検証失敗・判定不能は成功と報告しない。必要な保留・例外の管理は既存規程に従う。

## 4. スレッド間の役割分担

- 共通・言語別規約の提案、検討、正式制定は原則XO-Code Bustersのスレッドで行い、正本リポジトリで管理する。
- プロジェクト固有規約の検討と、制定済み規約の確認・適用は各プロジェクトのスレッドで行う。
- スレッド移動のみで文脈が完全に継承されるとは想定せず、正式な提案・判断・保留・変更結果は所定のGitHub記録に残す。

## 5. この工程の目標

目標は、複数プロジェクトで規約を参照・確認・適用し、コードレビューで発見した必要事項を継続的に規約へ追加・改訂できる**仕組みと手順**を整えること。
規約本文の網羅的な完成は目標としない。動作確認のために少数のサンプル規約を用いてよい。

## 6. 未検証事項

この文書は合意した運用手順を記録するものであり、複数プロジェクトからの実際の参照、候補抽出、適用、検証が成功したことを示さない。
これらの実装・検証時には、目的、成功・失敗・判定不能の条件、手順・比較対象・回数・停止条件を事前に明示する。
