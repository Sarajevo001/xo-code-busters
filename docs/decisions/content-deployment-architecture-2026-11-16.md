# 複数プロジェクトの公開・デプロイ責務に関する設計判断（2026-11-16）

## 決定したこと

1. XO-Code BustersがVPSの公開基盤（Caddy、公開URLの割当、共通デプロイ機構と運用手順）を管理する。講座・RPGなどの各リポジトリは、自身のソース、公開対象ディレクトリ、公開形式の宣言を管理する。
2. XO側は講座固有の内部ディレクトリ構造をハードコードせず、各リポジトリの公開定義を共通インターフェースで読み取り、公開処理を実行する。
3. 今回のプレゼン工房の講座は静的ファイルのみを公開する。今後も静的ファイルを基本とするが、動的アプリなどが必要になれば別途設計判断を行う。
4. 静的公開では、GitHubからVPSへクローン・更新したリポジトリ内の公開専用ディレクトリをWebサーバーが直接参照する。必要ファイルを別の公開用ディレクトリへコピーする方式は目標構成として採用しない。
5. 公開用ディレクトリの外にあるソース・設定・制作資料はWeb公開対象にしない。各リポジトリは公開内容を明示する。
6. Caddyなどの基盤設定はXO側のGitHubで管理し、稼働中のVPSへの適用はGit更新とは別の操作として扱う。公開URLやVPSの実配置先の最終決定・衝突防止はXO側の責務とする。

## 判断理由

- 講座が増えてもXO側に講座別のデプロイ実装を増やさずに済むようにするため。
- 公開対象と非公開対象を各リポジトリで明確に分離するため。
- GitHubを正本として、公開内容の更新を単純にし、コピー先との二重管理を避けるため。
- コンテンツの責務と公開基盤の責務を分離するため。

## 現状と目標構成の差分（2026-11-16）

- VPSで確認されたCaddy設定では、`demo.sarajevo.jp` のドキュメントルートは `/var/www/demo`。
- `/var/www/demo/oop-rpg-workshop` はシンボリックリンクではなく独立した実ディレクトリであることを確認済み。
- RPGのGitクローン先は既存作業記録では `/srv/GitHub/Sarajevo001/oop-rpg-workshop`。このクローン内の公開専用ディレクトリを直接参照する目標構成への切替は未完了。
- XO側のGit管理Caddyfileには `sarajevo.jp` の設定のみがあり、VPSの現行設定にある `demo.sarajevo.jp` が未反映。現行設定を精査してGitHubに保存する作業が残る。
- 既存 `deploy/deploy-xo.sh` はXO自身のデプロイ用であり、複数プロジェクト向け共通インターフェースは未実装。
- この文書のコミットだけではVPSの公開設定、公開先、デプロイスクリプトは変更されない。

## 未決定事項

- 公開定義ファイルの名称・形式・必須項目・バージョン
- 各講座の公開URLの命名規則、実際のCaddyへの割当方式
- 公開ディレクトリを直接参照するためのパス設計と必要なファイル権限
- 共通デプロイ処理の起動方式と異常時の扱い
- 動的アプリケーションを扱う場合の追加仕様

## 後続作業

1. 各リポジトリの公開定義とXO側の共通インターフェースを確定する。
2. RPGを含む対象プロジェクトを、Gitクローン内の公開専用ディレクトリを直接参照する構成へ移行する。
3. VPSの現行Caddy設定をGitHub側の管理ファイルに反映し、必要な設定変更を適用する。
4. 旧コピー先・旧スクリプト等の不要物を整理する。
5. 必要最小限の公開画面確認で完了判定する。不要な復旧訓練や網羅試験は実施しない。
