# ユーザー管理基盤の設計判断（2026-10-21）

## 決定したこと

1. 一般ユーザー向けWeb/APIと管理者向けWeb/APIを分離する。利用者とログイン画面も別体系にする。
2. 管理者サイトのURLは `admin.sarajevo.jp`。一般ユーザー向け `sarajevo.jp` と分ける。
3. 両系統が使用するサーバー側共通処理を `src/shared` に置く。共通コードと共通の実行サービスを混同せず、別サーバー化を妨げない。
4. 初期は同一VPS上の別Expressプロセス（3000、3001）、将来は一般ユーザー、管理者、DBを物理分離可能な構成とする。
5. 先に画面モックで操作と仕様を確認する。認証方式、セッション、DB設計はこの段階では決めない。
6. 認証未実装の管理者画面は公開しない。設定ファイルはドラフトのままとし、デプロイは別途承認する。

## 判断理由

- 管理者と一般ユーザーの責務・アクセス境界を明確にするため。
- DBアクセス基盤やログ等の重複実装を避けながら、サービスの独立性を維持するため。
- 画面操作の確認と認証・DBの本実装を混同せず、段階ごとの完了判定を可能にするため。

## 未決定事項

- 認証方式、管理者アカウントの発行・管理方式、セッション方式
- DBスキーマ、アクセス権限、管理API仕様
- 管理者サイト公開時のDNS・Caddy反映とデプロイ手順の最終確定

## 実装の現状

`src/shared` と `src/admin-server` の骨組み、双方の画面モックをGitHubに登録済み。動作検証と公開は未実施。詳細は [画面仕様](../specification/user-management-screens.md) と [構成設計](../specification/user-management-architecture.md)。
