# ユーザー管理 画面仕様（モックアップ段階）

最終更新：2026-10-21

## 1. 目的と適用範囲

一般ユーザーと管理者の画面構成・操作フローを確認するための仕様。現段階は仮データによる画面モックアップであり、認証方式、セッション方式、DB設計、API仕様の確定資料ではない。

## 2. 利用者と識別子

- 一般ユーザーと管理者は独立した利用者群・ログイン画面とする。
- 一般ユーザーのログイン識別子はメールアドレス。内部ユーザーIDは自動採番し、表示名と区別する。
- 一般ユーザーは自分のアカウントのみ参照・編集する。管理者は一般ユーザーの登録、検索、編集、利用停止・解除、パスワード再設定を担当する。
- 管理者同士の権限差は当面設けない。管理者認証方式と管理者アカウント管理方法は未確定。

## 4. 画面遷移

一般ユーザー：公開トップ → ログインまたは新規登録 → ログイン後ホーム → アカウント設定／アプリ → ログアウト。将来は未ログインのアプリアクセス時にログイン画面へ誘導し、ログイン後に要求元アプリへ戻す。

管理者：ログイン → ユーザー一覧 → 詳細 → 編集、または一覧 → 新規登録。ログアウトでログイン画面へ戻す。ダッシュボードは今後の画面追加対象。

## 5. 入力・操作上の決定事項

- 一般ユーザー登録：メールアドレス、表示名、パスワード、パスワード確認を必須とする。
- 管理者による一般ユーザー登録：メールアドレス、表示名、初期パスワード、確認を必須とし、新規ユーザーは有効状態とする。
- メールアドレスは一般ユーザー間で重複不可。
- 管理者はパスワードの閲覧を行わず、再設定のみ可能とする。
- 開発専用の「テストユーザーでログイン」は一般ユーザー側のみ。将来の本実装ではサーバー側で本番無効化する。
- パスワード照合、保存方式、認証トークン・セッション、権限チェック、エラーメッセージ詳細は本実装時に設計する。

## 6. 実装済みと未実装の境界

- 一般ユーザーモック：`src/client/mock.html` と `src/client/js/user-mock.js`。既存の `src/client/index.html` は変更していない。
- 管理者モック：`src/admin-client/index.html`、`app.js`、`styles.css`。
- 仮データはブラウザのメモリ内で扱い、再読込で初期化。入力パスワードは保存しない。
- 管理者モックのログインは入力必須チェックと画面遷移のみで、本人確認は行わない。
- 現状の管理者Expressは管理画面を配信しない。一般ユーザー向け既存アプリもログイン必須にはなっていない。
- ブラウザ実機検証、仕様レビュー、モック完成判定は未実施。コードがあることと動作確認済みであることを区別する。

## 7. 今回の完了条件

双方の画面をブラウザで確認し、主要遷移、入力項目、仮登録・仮編集・ログアウトをレビューして修正点を反映した時点でモック完成と判定する。認証・DBの本実装は別工程。
