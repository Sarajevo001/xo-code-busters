# XO-Code Busters プロジェクト運用ガイド

最終更新：2026-08-22

## 1. 目的

この資料は、

「設計判断を持ち寄る開発研究会 ～XO-Code Busters 奮闘記～」

およびXO-Code Busters Webアプリケーションについて、資料・成果物・イベント情報をどこで管理・公開するかを統一するための運用ガイドです。

毎回の開催時に運用方法を考え直さなくて済む状態を目的とします。

---

## 2. 情報の役割分担

### connpass グループページ

研究会そのものについて説明する場所。

掲載対象：

- 研究会の目的
- 活動方針
- 継続的な説明
- GitHub等への導線

毎回変わる情報は原則として掲載しません。

---

### connpass イベントページ

各開催回について説明する場所。

掲載対象：

- 開催日時
- 会場
- 募集人数
- 当日の予定
- その回固有の連絡事項

前回のイベントをコピーして作成し、その回で変更される情報を更新します。

---

### GitHub

プロジェクトの成果物および開発履歴の正本。

掲載対象：

- ソースコード
- 開発ロードマップ
- 運用ガイド
- 設計資料
- 判断ログ
- 調査資料
- プレゼン資料

GitHubを技術的成果物の中心とします。

---

## 3. イベントごとの資料

研究会で発表・検討した資料については、内容に応じてGitHubで管理します。

例：

```text
docs/
├── overview/
├── operation/
├── specification/
├── decisions/
├── research/
└── presentations/
```

### research

調査過程や技術検証の記録。

例：

- Node.js標準HTTP機能の調査
- Express採用検討
- OAuth / OpenID Connect調査
- JavaScriptにおけるOOP実装の検証

### presentations

研究会等で実際に発表するために作成した資料。

発表資料の元データおよび、必要に応じてPDF等の配布形式を保存します。

---

## 4. connpassからの資料公開

connpassを成果物そのものの保管場所にはしません。

資料は原則としてGitHubで管理し、connpassから必要な資料への導線を設けます。

### グループページから案内するもの

継続的に参照してほしい情報。

例：

- GitHubリポジトリ
- プロジェクト概要
- 開発ロードマップ

### 各イベントページから案内するもの

その開催回と強く関連する情報。

例：

- 当日の発表資料
- その回で扱った調査結果
- その回で完成した成果物

---

## 5. Git運用

GitHubを正本とします。

### 開発PC

Ubuntu上の、

`~/develop/xo-code-busters`

で作業します。

Visual Studio Codeを主な編集環境として使用します。

基本操作：

編集  
↓  
差分確認  
↓  
Commit  
↓  
Push  
↓  
GitHub

---

### VPS

VPSは原則としてデプロイ先として扱います。

VPS上で直接ソースコードを編集しません。

基本操作：

GitHub  
↓  
Git Pull  
↓  
アプリケーション実行・再起動

---

### スマートフォン

軽微なMarkdown資料の追加・更新等については、必要に応じてGitHub Webから操作します。

本格的なソースコード編集についてはUbuntu + Visual Studio Codeを使用します。

---

## 6. ドキュメント更新ルール

### roadmap.md

以下に変化があった場合に更新します。

- 作業が完了した
- 新しい作業を開始した
- 次に行う作業が変わった
- 技術構成が決定・変更された
- プロジェクトのフェーズが変わった

ロードマップには詳細仕様を書き込みすぎません。

---

### project-operation-guide.md

以下に変化があった場合に更新します。

- connpass運用方法を変更した
- GitHubでの資料配置ルールを変更した
- 成果物の公開方法を変更した
- 開発・デプロイ運用を変更した

---

### 判断ログ

設計上意味のある判断を行った場合に記録します。

単なる作業履歴ではなく、

「なぜそうしたのか」

を後から説明する必要があるものを対象とします。

---

## 7. 基本原則

資料を作ること自体を目的にしません。

必要な情報を、

**必要な人が、必要なときに、適切な場所から参照できること**

を優先します。

また、ドキュメント構成についても最初から完成形を固定せず、実際に必要になったものを追加していきます。
